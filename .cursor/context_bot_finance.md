## К3 траты (выписка карты → ручные транзакции)

Эталонный прогон: **11.08.2026** · Альфа выписка PDF `Выписка_по_счёту.pdf` · период 07–11.08 · 8 HOLD · 10 357 ₽ → ids `633–640` на Selectel.

Цель: разнести операции **как будто я вбил их в миниаппе** (каждая строка = отдельная транзакция на **дату операции**, не дату выписки). Код не меняется — это запись в **прод-БД Selectel**, не локально и не Amsterdam.

### Алгоритм (строго)

1. **Выписка.** Пользователь кидает PDF/CSV/Excel/путь к файлу. Разобрать **все исходящие** операции: покупки, HOLD, **СБП/переводы**, платежи, **внутрибанк с дебета** (в т.ч. на накопительный). Дата операции (не «дата проводки HOLD» и не дата формирования выписки), описание как в банке, сумма модуль ₽. Сверить с шапкой «Расходы N RUR». Транши выдачи кредита (`CR60`) и входящие — не расход; в матрицу не тащить (или отдельно пометить как «не расход»).
2. **Предположения агента.** В чат — нумерованная матрица (markdown-таблица). **Canvas / отдельный артефакт — запрещены.** Колонки: `№ | Дата | Описание (как в банке) | Сумма | Категория | slug | Комментарий`. Одна строка = одна будущая запись. **Не сливать** одинаковые merchant в один день (два Mos.Transport 380+380 = две строки). Переводы — тоже строки матрицы (догадка slug или «уточни»); **не пропускать молча**. Неясное помечать «уточни», но всё равно предложить slug.
3. **Стоп.** Пока пользователь **сам не распределил каждую** строку — в БД **не писать**. Формат правок свободный: `1 2 3 подарки 4 5 6 7 еда 8 проезд` или `3 → raznoe` / `2 пропустить`. Агентские догадки (`kafe` vs `eda`, транспорт vs подарки) **не истина** — истина только ответ пользователя.
4. **Матрица после правок.** Прислать обновлённую таблицу (уже с его slug) + сводку по категориям + итого. Если пользователь сказал «пропустить» — выкинуть строку и пересчитать сумму.
5. **Сразу Selectel.** Как только категории подтверждены (или явно «пиши на селектел») — **сразу писать в прод**, без локальной БД, без второго круга «точно?». Amsterdam / WG не трогать. `./deploy/deploy-dual.sh` для этого шага **не нужен** (UI/API не менялись); «деплой на Selectel» = запись в `life_dashboard` на `161.104.47.52`.

### Как писать на прод

API с Mac без `tgWebAppData` отвечает **404** (TelegramGate) — через HTTP не ходить. Писать SQL:

```bash
# 1) id категорий с прода (не хардкодить вслепую)
ssh root@161.104.47.52 \
  "docker exec -i life_dashboard_pg psql -U lifeapp -d life_dashboard -c \
   \"SELECT id, slug, name FROM finance_categories WHERE slug IN ('eda','podarki','proezd',...);\""

# 2) INSERT по одной строке на дату операции, source = manual
ssh root@161.104.47.52 \
  "docker exec -i life_dashboard_pg psql -U lifeapp -d life_dashboard -v ON_ERROR_STOP=1" <<'SQL'
BEGIN;
INSERT INTO finance_transactions (tx_date, category_id, amount, income_note, source) VALUES
  ('2026-08-10', 19, 380.00, NULL, 'manual'),
  ...
RETURNING id, tx_date, category_id, amount;
COMMIT;
SQL
```

Ориентиры id на проде (проверить SELECT-ом): `eda=10` · `podarki=19` · `proezd=13`. После INSERT — таблица `id | дата | slug | сумма` пользователю.

### Нюансы модели (иначе сломается «как будто я»)

- Таблица `finance_transactions`: `tx_date`, `category_id`, `amount`, `income_note`, `source`. **Merchant/комментарий в расход не пишется** — API расходные заметки отвергает (`Заметка допустима только для доходов`). Описание живёт только в матрице чата.
- `source = 'manual'` — как ручной ввод в UI (история фильтрует `source === "manual"`). Не `excel_import`.
- Сумма **положительная** (модуль); знак минуса из выписки отбросить. Разделители банка (`6 480,00` / `-6 480,00 RUR`) → `6480.00`.
- Дата = **дата операции** из текста HOLD (`дата операции: 10.08.2026`), ISO `yyyy-MM-dd`. Не дата снятия холда и не дата формирования PDF.
- **HOLD тоже пишем**, если пользователь не сказал пропустить: в миниаппе нет статуса «неподтверждено», это обычный расход. Дубль после клиринга банком не импортировать повторно — сверять сумму+дату+категорию за день.
- Не использовать `api/import_finance.py` — это помесячные агрегаты Excel, не пооперационка.
- Карта может быть на другое ФИО (в эталоне — Рыбальченко Д. Л.) — в семейные финансы всё равно, если пользователь прислал выписку.
- Возвраты/кэшбек — не класть в расход, пока пользователь явно не сказал куда.
- **Переводы с дебета (СБП, внутрибанк, на накопительный, погашение карт)** — всегда в матрицу; пользователь разметит (`ipoteka` / `technika` / `nakopleniya_dasha` / `пропустить` и т.д.). Молча не игнорировать.
- **VENDING METRO4** / **EKSPRESS VENDING METR** — перекусы Даши в метро → `eda`.
- Slug расходов (частые): `eda` `kafe` `proezd` `taksi` `avto` `ipoteka` `kvartplata` `svyaz` `dom_remont` `technika` `rebenok` `nakopleniya_dasha` `podarki` `zdorovie` `krasota` `sport` `obuchenie` `razvlecheniya` `internet` `assets_10` `nalogi` `biznes` `raznoe` `odezhda` `otpusk`. Обзор склеивает `eda+kafe` → «Питание», `podarki` → «Накопления и подарки».
