## Контекст продукта

MVP рутина/спорт уже в mini-app (см. context_bot_miniapp.md). Дальше — модуль питания **под** главным дашбордом (не в KPI 2×2), по духу **Cronometer** (только нужные части):

1. **Горизонтальные полоски** дня: калории, белок, жиры, углеводы, **клетчатка** — факт vs цель.
2. **База продуктов** — карточка продукта (название, КБЖУ и клетчатка на порцию/100 г).
3. **Добавление в день** (приёмы / группы как в Cronometer: Breakfast, Lunch…).
4. **Суммирование за день**.
5. **Таргеты КБЖУ** в зависимости от нагрузки: **вело → бег → воркаут → отдых** (логика уже есть текстом в `bot/kbju.py` — использовать как стартовые диапазоны, потом в БД/конфиг).

**Вне scope сейчас:** микронутриенты, витамины, вода, алкоголь, омега, аминокислоты и прочие 50+ колонок CSV.

## Исходные данные Cronometer

Файл: `servings.csv` (экспорт Cronometer).

Ключевые колонки для MVP:
- `Day`, `Group`, `Food Name`, `Amount`
- `Energy (kcal)`, `Protein (g)`, `Fat (g)`, `Carbs (g)`, `Fiber (g)`

**Проблема кодировки:** при выгрузке русские названия («база добавок», «яйцо вареное») иногда превращаются в «иероглифы» — это неверная кодировка при открытии/импорте (UTF-8 vs Windows-1251/cp1251).  
**Перед импортом:** проверь файл командой `file -I` и Python `utf-8` / `utf-8-sig` / `cp1251`; в API импорта — явный encoding, нормализация NFC. Не править руками тысячи строк — починить пайплайн импорта.

Пример строк (UTF-8 читается нормально):
- «база добавок на сутки (33 протеина 7 клетчатки)»
- «яйцо вареное с 0 вв», «филе грудки петелинка»

## Технические ориентиры

- **Бэк:** новые таблицы Postgres + эндпоинты в `api/` (по стилю `day_read.py` / `month_read.py`).
- **Фронт:** `mini-app/` — секция `#nutritionZone` (или аналог) **под** кнопкой «Заполнить», скрывать на fill/detail как KPI.
- **Связь со спортом:** таргет дня из записанного спорта за день (те же колонки, что `classify_sport_day` в `bot/kbju.py`) или ручной выбор «тип дня».
- **Импорт CSV:** одноразовый скрипт `api/import_cronometer.py` или `!bot_SQL/` — дедуп продуктов по имени, servings → `food_log`.
- Минимальный diff; не переписывать mini-app с нуля; cache-bust при смене CSS/JS.
