> Копия для Finder: этот файл лежит рядом с `index.html`. Для Cursor: `.cursor/context_html_appscript.md` (дашборд) и `.cursor/context_bot_appscript.md` (бот). См. `.cursor/README.md`.

## Проект

— **Название:** дашборд «сферы жизни» + спорт (минуты) — MVP.  
— **Цель:** визуализация прогресса по сферам (факт/цель 0–1 и агрегаты) и по спорт-метрикам (минуты в колонках «…, min») с обновлением с Google Sheets; доступ с десктопа и при желании с телефона (GitHub Pages).  
— **Стек:** статический `index.html` + Chart.js (CDN), данные через **Google Apps Script** Web App (`…/exec`, JSON), источник — **Google Sheets**. Без React/Vue и без бэкенда своего.

## Что сделано

— Листы таблицы по месяцам: имя вкладки = **`yyyy-MM`** (например `2026-05`).  
— **Сферы жизни:** шапка `B1:I1`; дневные строки с датой в `A` и 0/1 в `B:I`; итоги — строки с метками в **`A`:** `факт` и `цель` (номера строк **не фиксированы**, зависят от 28–31 дня). При нескольких `цель` для сфер берётся строка с **максимальной суммой B:I**.  
— **Спорт (минуты):** только столбцы **J, K, N, P, T** (1-based). Факт = сумма по всем строкам, где в `A` **дата**. Цели по категориям = ячейки **J, K, N, P, T** в строке с **`цель`**, выбранной так: среди всех `цель` — максимум суммы **J+K+N+P+T**; если везде 0 — fallback на строку `цель` с макс. суммой **B:I** (как сферы).  
— **Итог спорта в UI:** `Итог <месяц> <год>: факт / N (%)`; знаменатель **N** из объекта **`SPORT_ITOG_MINUTES_GOAL[yyyy-MM]`** в Apps Script (напр. 1417 для мая), иначе сумма пяти целей из строки, иначе fallback из скрипта. Процент итога с **одним десятичным**.  
— Плашки спорта: `категория: факт / цель мин (%)` с теми же цветами порога, что и сферы (&lt;50 красный, 50–99 жёлтый, ≥100 зелёный).  
— Диаграммы: **Факт vs цель** (синий `#4e79a7` / оранжевый `#f28e2b`) для сфер и так же для спорта по категориям; radar **факт/цель** 0..1 для сфер; PNG-экспорт; выбор месяца на странице + плашка «текущий месяц».  
— Автообновление **30 с**; **localStorage:** последнее успешное обновление и лог ошибок API (до 10).  
— **«Дни подряд»** по сферам — пробовали, затем **удалили** из продукта (сложность с датами/деплоем); в текущем API нет `streaks`.  
— Пробовали **равномерное деление** месячной цели по всем колонкам «, min» в J:V — **отвергнуто**; цели спорта только из **J,K,N,P,T** в **динамически найденной** строке **`цель`**.

## Текущее состояние

— Остановились на: **стабильный MVP** с динамическими строками `факт`/`цель`, спорт по **J,K,N,P,T** и итогом через **`SPORT_ITOG_MINUTES_GOAL`**, контекст зафиксирован для новых чатов.  
— **Работает:** загрузка JSON, графики сфер, блок спорта, выбор месяца, цвета, PNG, автообновление, локальный лог ошибок — при корректном **Deploy** Web App (`Execute as: Me`, `Anyone`) и актуальном **`API_URL`** в `index.html`.  
— **Не в скоупе / не доведено:** финальный выбор альтернативных визуализаций (обсуждались текстом); публикация на GitHub Pages — инструкция давалась, не подтверждено что задеплоено; отдельная строка `цель` только для спорта при «нулевой» строке сфер — краевой случай.

## Архитектурные решения

— **Один Web App URL** на таблицу; смена месяца — query **`month=yyyy-MM`**, лист = имя месяца.  
— **Сферы и спорт цели** на одной строке `цель` (рекомендуется): одна правда в таблице; при двух строках `цель` спорт привязан к max **J–T**.  
— Итог минут спорта **1417** может не совпадать с суммой пяти ячеек целей — тогда явно **`SPORT_ITOG_MINUTES_GOAL`**.  
— Фронт не парсит таблицу — только JSON; любая смена логики в **Apps Script** + **Edit deployment → New version → Deploy**.

## Критический контекст

— **После любого изменения `doGet`:** Save → **Manage deployments → Edit → выбрать New version → Deploy**; иначе `/exec` отдаёт старый код.  
— **`index.html`:** открывать через **`python3 -m http.server`** (или хостинг), не как RTF в TextEdit; **`API_URL`** без лишних query при сборке базы (месяц добавляется в коде).  
— **Не смешивать:** дневные 0/1 сфер (A:I) и спорт-столбцы J–T; итог сфер — строки `факт`/`цель` по **B:I**; спорт-цели — **J,K,N,P,T** в выбранной строке `цель`.  
— Поле в JSON **`goalSumSportTargets`** (раньше могло называться `goalSumRow34`) — сумма целей из найденной строки; **`sportGoalRow1Based`** — для отладки.  
— Удалены **`streaks`** из продукта; старые ответы API с `rows` без `sport` — фронт должен gracefully обрабатывать `sport` (проверки в `renderSport`).
